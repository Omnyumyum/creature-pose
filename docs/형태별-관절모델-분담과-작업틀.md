## 2. 작업 틀: 형태 하나를 만드는 6단계

육도현이 4족형으로 한 순서를 그대로 일반화한 것이다. **모든 형태가 이 순서와 파일 이름 규칙을 따른다.**

| 단계 | 무엇 | 4족형에서 쓴 파일 (본보기) | 새 형태에서 만들 파일 |
|---|---|---|---|
| ① 합성기 | 정답 관절을 아는 몸 마스크를 프로그램으로 그림. 학습 그림의 대부분이 여기서 나옴 | `train/synth_quad.py` | `train/synth_<형태>.py` |
| ② 시험 세트 후보 | 진짜 그림 후보 모으기 (Quick, Draw! + 직접 그림 + 아이 그림은 로컬만) | `tools/build_testset.py`, `tools/build_qdset.py` | `tools/build_<형태>set.py` |
| ③ 정답 표시 | 시험 세트 20 ~ 30장에 사람이 관절을 찍음 | `tools/make_labeler.py` + `tools/label_server.py` (4족 전용) | `tools/<형태>_labeler.py` (날개형 `wing_labeler.py` 를 본뜸, 표준 라이브러리만) |
| ④ 규칙 점수 | 지금 서비스 규칙을 같은 시험 세트로 채점 (비교 기준선) | `tools/score_rule.py` | 같은 파일에 형태 추가, 또는 `tools/score_rule_<형태>.py` |
| ⑤ 학습 | `train/multi_model.py` 의 `FORMS` 에 한 줄 더하고 그 형태만 따로 학습 | `quad_model.py`, `multi_model.py --forms quad` | `FORMS["<형태>"] = {...}` 한 줄, `--forms <형태>` |
| ⑥ 시험 · ONNX | 시험 세트로 규칙 vs 모델 → 나으면 ONNX 로 바꿔 서버에 넘김 | `quad_model.py test` | `multi_model.py test --forms <형태>` (공통으로 만들 것), `tools/export_onnx.py` (공통, 서민지) |

### 2-1. 단계마다 지킬 약속 (4족형에서 정한 것 그대로)

**① 합성기**
- `generate(rng) -> (마스크 bool SxS, 관절 Kx2)` 꼴. `ORDER` 에 관절 이름 순서. `python train/synth_<형태>.py 24` 로 `work/synth_<형태>_look.jpg` 눈으로 보기.
- 관절 자리는 **서비스 규칙과 같은 약속**으로 놓는다 (서비스 `drawtale-ai runtime/ai_server/<형태>.py` 의 find_joints).
- 꼴을 여러 가지(예: 옆모습 · 위에서 본 것)로, 속이 빈 선 그림을 일부(약 15%) 섞는다.
- 서비스 관절 수와 다르면 `to_service()` 로 서비스 이름에 맞춘다 (날개형 5 → 8 처럼).

**② ③ 시험 세트**
- 후보를 넉넉히(약 60장) 모으고 표시할 때 「못 씀」으로 걸러 **20 ~ 30장**.
- 정답 초안은 **규칙 · 모델이 아니라 고정 자리**에서 시작한다 (초안 낸 쪽에 유리해지지 않게. 날개형 도구 방식).
- 그림 · 정답은 `data/testset/<형태>/` (커밋 안 함). 아이 그림은 `kids_NN.png` 로 로컬에만.
- 표시 도구 포트는 겹치지 않게 (아래 2-3 표).

**④ ⑥ 채점**
- 점수: 몸 크기 대비 거리 **PCK@0.1 · PCK@0.2**, 「받은 그대로 / 세워서」 두 조건.
- 규칙과 모델을 **같은 시험 세트, 같은 채점**으로 나란히.
- 좌우 뒤집어 한 번 더 보고 평균(`quad_model.predict` 기본)을 모든 형태에 똑같이.
- 씨앗(seed)만 바꿔 여러 번 돌려 평균을 본다 (4족형은 4번). 29장 시험이라 몇 %는 오차.

**⑤ 학습**
- 입력 · 늘리기 · 히트맵은 `quad_model.py` 와 같다: 마스크를 감싼 정사각형(긴 변 × 1.25)을 **256 × 256**, 출력 **64 × 64 히트맵**, ResNet-18(ImageNet).
- **형태마다 따로 학습한다** (11/20 결과: 같이 학습하면 4족이 약 5%p 낮음).
- 기본 설정: `--synth 5000` (에폭마다 합성 5,000장), 60 에폭. 사람 정답이 있으면 섞는다.
- 누운 사진은 모델에 맡기지 않는다 (돌리기 ±180도는 오히려 떨어짐). 서비스에서 먼저 세운다.
- 모델 이름: `models/<형태>_<tag>.pth`, 기록 `out/<형태>_<tag>.json`.

## 3. 형태별 할 일

### 3-1. 날개형 (서민지, 넘겨받음)

**넘겨받는 것 (육도현 11/20 작업)**
- `train/synth_wing.py`: 옆모습 새 70% · 위에서 본 나비 · 잠자리 · 앞모습 새. 날개 하나 기준 관절 5개(body · head · wing_root · wing_mid · wing_tip), `pick_one` · `to_service`.
- `tools/build_wingset.py`: Quick, Draw! 7종(bird · duck · owl · parrot · butterfly · mosquito · bee) × 7 + 직접 그림 3 + 합성 6 = 후보 58장.
- `tools/wing_labeler.py` (포트 8770): 점 4개(몸통 · 머리 · 날개 뿌리 · 끝), 가운데 자동, 날개 있음 · 없음, 못 씀.
- 정답 2장 (새 형식).
- `multi_model.py` 의 `FORMS["wing"]`. 이전 8점 학습(`w1` · `m1`)의 날개 쪽은 버림.

**남은 일**

| # | 할 일 | 끝 기준 |
|---|---|---|
| 1 | 후보 58장 정답 표시 → 20 ~ 30장 확정 (+ 로컬 아이 그림) | `data/testset/winged/labels.json` |
| 2 | 서비스 규칙(`winged.py`) 채점: 받은 그대로 / 세워서 | 규칙 기준선 |
| 3 | `w2` 학습 (날개만, `--synth 5000`), 씨앗 바꿔 여러 번 | `models/wing_w2*.pth` |
| 4 | 규칙 vs 모델 비교, 11/26 렌더링 실패 원인 「머리 · 몸통 못 나눔 30장」이 풀리는지 따로 봄 | 비교표 |
| 5 | ONNX 변환, `to_service` 로 서비스 8관절에 맞춰 서버 연결 | 서버에서 같은 좌표 |

### 3-2. 지느러미형 (서민지, 새로)

**관절 (서비스 `finned.json`)**: head · b1 · b2 · b3 · tail (5개, 머리에서 꼬리까지 몸 축을 따라).

| # | 할 일 | 메모 |
|---|---|---|
| 1 | 서비스 규칙(지느러미형 find_joints)에서 관절 놓는 약속 확인 · 정리 | 머리 쪽 정하는 법(눈 자리), b1 ~ b3 간격 |
| 2 | `synth_fin.py`: 방추형 · 타원 몸 + 꼬리지느러미(갈래 · 둥근) + 등 · 배 · 가슴지느러미 + 눈 자리. 옆모습 기준, 몸 휨 조금, 속 빈 선 그림 15% | 고래 · 상어처럼 긴 몸, 복어처럼 둥근 몸 모두 |
| 3 | `build_finset.py`: Quick, Draw! fish · whale · shark · dolphin 등 + 직접 그림 + 아이 그림(로컬) | 후보 약 60장 |
| 4 | `fin_labeler.py` (8771): 점 = 머리 · 꼬리 (+ 필요하면 몸 가운데), b1 ~ b3 는 몸 축 따라 자동 | 날개형 도구 본뜸 |
| 5 | 규칙 채점 → `FORMS["fin"]` 학습 → 비교 → ONNX → 서버 | 2장 순서 그대로 |

### 3-3. 4족형 · 사슬형 · 여러 다리형 (육도현)

| 형태 | 남은 일 | 메모 |
|---|---|---|
| 4족형 | v4 (군더더기 35% · 60%) 채점 → 가장 나은 것 확정 → ONNX | 마스크 군더더기(종이 가장자리 · 그림자 띠)가 크게 틀린 원인이었음 |
| 사슬형 | `synth_chain.py`(관 모양 몸을 곡선 따라, 굵기 고름), 시험 세트(Quick, Draw! snake 등), 관절 8(head · b1 ~ b6 · tail) | 똬리처럼 겹친 몸은 지금도 안 됨. 시험 세트에 넣을지 정하기 |
| 여러 다리형 | 다리 수가 그림마다 다름(최대 8, 관절 25). 「없는 다리는 점수 0」 같은 표현 방식부터 정하기 | 가장 어려움. 12/5 까지 안 되면 규칙 유지 |

1. 저장소 공유: 서민지를 `creature-pose` 협업자로 넣기, 브랜치 규칙(2-2) 확정
2. 학습 장소: 집 PC 같이 쓰기(원격 순서) 또는 Colab
3. 공통 파일 고칠 때 확인 방식 (`common/` 브랜치)
4. 지느러미형 관절 약속 (머리 쪽 · b1 ~ b3 간격)
5. 여러 다리형 표현 방식, 안 되면 규칙 유지 결정 시점
6. 형태별 스위치 켜는 기준 (규칙보다 몇 %p 나으면)
7. 저장소 공개 여부
