## 0. 한 줄 요약

- **형태 5종 모두** 관절 모델로 바꾼다. 모델은 육도현이 학습해 **ONNX** 로 넘기고, 서민지가 서버에 붙인다.
- **분석 거절**은 서버가 실패 이유를 알려 주는 신호 3개를 만들고(서민지, 11/30 까지), 화면이 그 신호로 이유별 안내를 보여 준다(육도현, 12/1 부터).
- **장면 소품 배치**는 둘이 같이 **규칙 기반**으로 한다. 서버는 「무엇을 어디에」, 화면은 「그리기 · 보여 주기」.

## 2. 공통 사항 (둘이 같이 지킬 규격)

### 2-1. 형태 모델 ONNX 규격

**모델을 넘길 때 함께 주는 것 (형태마다)**

| 물건 | 예 | 왜 |
|---|---|---|
| ONNX 파일 | `quadruped_v1.onnx` | 서버가 돌릴 파일 |
| 관절 이름 목록 (순서대로) | `quadruped_v1.joints.json` | 출력 순서를 서비스 관절 이름에 맞춤 |
| 전처리 설명 | 입력 크기, 마스크 값(0/1 인지 0/255 인지), 여백, 좌우 뒤집기 평균 여부 | 서버가 학습 때와 똑같이 넣어야 결과가 같다 |
| 변환 코드 | PyTorch → ONNX 셀 또는 스크립트 | 다시 학습하면 다시 변환 |
| 시험 세트 점수 | 지금 규칙 vs 모델, 같은 시험 세트 | 스위치를 켤지 정하는 근거 |
| 확인용 3장 | 그림(마스크) 3장과 그때 모델 출력 좌표 | 서버에서 같은 좌표가 나오는지 맞춰 봄 |

**입력 · 출력 (제안, 회의에서 확정)**

| | 규격 |
|---|---|
| 입력 이름 · 모양 | `input`, float32 `[1, 1, H, W]` 몸 마스크. H · W 는 형태마다 고정 (예: 256 × 256) |
| 출력 | `joints` float32 `[1, K, 2]` 좌표(입력 크기 기준 0 ~ 1), `scores` float32 `[1, K]` |
| 디코드 | 히트맵 · SimCC 를 좌표로 바꾸는 일은 **ONNX 안에 넣는다** (서버는 좌표만 받음). 넣기 어려우면 디코드 방식을 문서로 |
| 좌우 뒤집기 평균 | 종합 문서 3-6 「예측 기본으로 넣음」. ONNX 안에 넣거나, 서버가 두 번 돌려 평균 (어느 쪽인지 표시) |
| opset | 17 (김민준 모델과 같음) |

**형태별 관절 (지금 서비스 정의, `drawtale-ai runtime/ai_server/forms/*.json`)**

| 형태 | 지금 관절 수 | 관절 | 확인할 것 |
|---|---|---|---|
| 4족형 `quadruped` | 18 | hip · torso · neck · 뒷다리 2 × 3 · 앞다리 2 × 3 · tail · tail_mid · tail_tip | 학습 정답 18개와 이름 · 순서가 같은지. 몸통 세 점은 서비스 규칙과 같은 식으로 계산(3-6) |
| 날개형 `winged` | **8** | body · head · wing1 (root · mid · tip) · wing2 (root · mid · tip) | **모델은 5개(날개 하나)**. 서비스를 5개로 줄일지, wing2 를 비워 둘지 정해야 함 |
| 지느러미형 `finned` | 5 | head · b1 · b2 · b3 · tail | |
| 사슬형 `chain` | 8 | head · b1 ~ b6 · tail | |
| 여러 다리형 `radial` | 25 | body · leg1 ~ leg8 (root · mid · tip) | 다리 수가 그림마다 다름. 「최대 8, 없는 다리는 점수 0」으로 할지 |

**파일 이름 · 버전**: `<형태>_v<번호>.onnx`. 다시 학습하면 번호를 올린다. 서버는 어느 버전으로 분석했는지 기록한다.

### 2-2. 서버 스위치와 되돌리기

| 환경 변수 (제안) | 값 | 뜻 |
|---|---|---|
| `FORM_MODEL_QUADRUPED` | 비움 / `quadruped_v1` | 비우면 지금 규칙, 이름을 넣으면 그 모델 |
| `FORM_MODEL_WINGED` · `_FINNED` · `_CHAIN` · `_RADIAL` | 같음 | 형태마다 따로 켬 |
| `POSE_PROVIDER` | `meta` / `a2` | 사람 관절 모델 (김민준). 같은 방식 |

- 모델이 실패하거나(파일 없음 · 오류) 점수가 기준보다 낮으면 **그 그림만 규칙으로 되돌아간다.**
- 분석 응답에 `pose_source: "model:quadruped_v1" | "rule"` 을 넣어 어느 쪽이 냈는지 화면 · 로그에서 볼 수 있게 한다.

### 2-3. 분석 거절 신호 (서버 → 화면 계약)

종합 문서 3-8 「서버에 필요한 것」을 계약으로 옮긴 것이다.

| 신호 | 어디에 | 값 | 언제 | 화면이 할 일 (3-8) |
|---|---|---|---|---|
| `RENDER_EMPTY` | 오류 코드 | | 렌더가 「성공」인데 그림이 비어 있음 (11/26 수집 5장) | 묻지 않고 한 번 자동 재시도, 또 비면 「다시 찍기」 |
| `cutout_warning` | 분석 응답 | `null` · `"edge"` · `"faint"` | edge: 잘라낸 그림이 사진 가장자리에 닿음. faint: 상자에 비해 너무 작거나 조각이 여럿 | S-05 에서 「친구만 보이나요?」 · 「진하게 따라 그려 볼까요?」 |
| `parts_missing` | 분석 응답 | `[]` · `["wing"]` · `["head"]` … | 관절은 찾았지만 일부 부위를 못 찾음 (날개 12장) | 거절하지 않고 몸 통째로 움직이기, 어른 화면에 「날개 자리 고치기」 |
| `joints_found` | 분석 응답 (있음) | `true` · `false` | 관절을 못 찾아 기본 뼈대 | 「모습 다시 고르기」 · 「몸 전체로 움직이기」 |
| 기존 코드 | 오류 코드 (있음) | `NO_CHARACTER_DETECTED` · `MULTIPLE_CHARACTERS` · `LOW_CONFIDENCE` · `ENGINE_TIMEOUT` | | 지금처럼, 단 문구를 **고른 형태에 맞게** (지금은 모두 「사람 모양」) |

**다시 분석 (다시 찍지 않고)**

| 요청 | 값 | 화면 버튼 |
|---|---|---|
| `rotate` | `0` · `90` · `180` · `270` | 「돌리기」 (누운 사진). 19장 v0.3 의 「바르게 돌리기」가 이미 있으면 그것을 쓴다 |
| `form` | 형태 id | 「모습 다시 고르기」 |

**기준값**(가장자리 몇 px 이내면 edge, 상자 대비 몇 % 미만이면 faint)은 서민지가 **11/26 수집 124장**으로 맞춘다. 정상 그림을 잘못 거르는 비율을 같이 적는다.

### 2-4. 장면 소품 배치 (규칙 기반, 같이)

## 6. 회의에서 정할 것

1. **ONNX 입력 · 출력** (2-1): 마스크 크기, 디코드를 ONNX 안에 넣을 수 있는지, 좌우 뒤집기 평균을 어디서 할지
2. **날개형 관절 8 ↔ 5**: 서비스를 날개 하나(5개)로 줄일지, wing2 를 비워 둘지
3. **여러 다리형**: 다리 수가 다른 그림을 모델이 어떻게 낼지 (최대 8, 없는 다리 점수 0?)
4. 3-8 「정할 것」 셋: 「몸 전체로 움직이기」를 아이 화면에 둘지 자동으로 넘어갈지, 누운 사진을 서버가 알아낼지, 기준값을 124장으로 맞출지
5. **장면 배치 응답 형식** (2-4)
6. 형태별 스위치를 켜는 기준: 시험 세트에서 규칙보다 얼마나 나아야 켤지
